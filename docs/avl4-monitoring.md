# Передача карточки из Monitoring в Flowsint

Реализация этапа 6. Код и локальные проверки готовы; живой стек, настройки
окружений и сквозная приёмка остаются этапом 7 [плана](avl4-integration-plan.md).

## Действие пользователя

Кнопка **«Добавить в расследование»** находится в верхней панели открытой
карточки: в ленте `/feed` и в окне карточки Analytics `/analytics`.
Она доступна для `shared_card` и `project_card`, если настроен Flowsint,
есть активный проект и доступ к Pulse/Flowsint и этому проекту.

1. Открыть карточку и нажать кнопку.
2. Выбрать расследование текущего проекта и его граф. В списке нет фильтра
   по создателю и отдельным ролям расследования.
3. При необходимости явно создать расследование и/или граф в этом диалоге.
4. Нажать **«Добавить карточку»**. Появятся ход операции, результат и ссылка
   **«Открыть в Flowsint»** с идентификатором проекта.

Исходная карточка не меняется. Flowsint сохраняет самостоятельный снимок,
происхождение и обратную ссылку на карточку Monitoring. Повторное добавление
в тот же граф показывает существующий материал. Обогащение не запускается.
Если содержимое исходника изменилось, обычная передача сохраняет существующий
снимок: API явного обновления описан в [контракте](avl4-card-transfer.md),
действие обновления снимка в этот диалог не включено.

## Запросы и состояние

- Списки и создание целей идут напрямую в публичный API Flowsint через
  опубликованный SDK `createPlatformAxios`: общий cookie, `h-avl-project`,
  проверка эпохи сессии и проекта при допуске ответа, обычный Auth Guard.
- Расследования: `GET /api/investigations`, создание:
  `POST /api/investigations/create`. Графы:
  `GET /api/investigations/{id}/sketches`, создание: `POST /api/sketches/create`.
- Передача идёт в Cards `POST /web/feed/cards/transfer-to-flowsint/`.
  Тело содержит только `operation_id`, `card_id`, `card_type`,
  `investigation_id`, `sketch_id`. Снимок, инициатор и проект берутся backend.
  UI отображает типы `shared_card/project_card`, контракт использует `shared/project`.
- На одно подтверждение создаётся один UUID операции. Ручной повтор после
  тайм-аута использует тот же UUID и ту же цель; поля цели блокируются после
  первой попытки. Автоматических повторов импортирующего запроса нет.
- Тайм-аут передачи — 35 секунд (backend Cards ограничивает вызов 30 секундами),
  запросов к целям — 15 секунд. Закрытие прекращает ожидание браузера;
  уже принятая сервером операция может завершиться. Новая отправка в тот же
  граф безопасна благодаря идентичности материала на backend.
- Создание целей не повторяется автоматически. После неоднозначного сбоя
  создания нужно обновить список: расследование или граф могли появиться.
- TanStack Query хранит списки, Zustand для нового сценария не используется.
  Диалог привязан к пользователю, эпохе сессии, проекту/ревизии и карточке.
  Смена контекста закрывает его, отменяет запросы и удаляет его query cache.
  Запоздалый результат не применяется. Обычная проверка сессии того же
  пользователя сохраняет диалог и выбор без повторной загрузки списков.
- Проверка контекста также выполняется после ожидания SDK, перед отправкой:
  отложенное создание или передача не переедет в другой проект.
- Ответы дополнительно проверяются по проекту, расследованию, графу и операции;
  ссылка допускает только HTTP(S), ожидаемый путь и правильный `pid`.
  Внутренние тексты ошибок не выводятся. Отказы, конфликт, недоступность и
  тайм-аут показываются отдельно; карточка остаётся в Cards.
- Используется нативный modal dialog. В Analytics он остаётся дочерним
  элементом окна карточки: выбор цели и Escape не закрывают родительскую карточку.

## Публичная настройка

В `monitoring-ui` runtime JSON поддерживается необязательное поле
`settings.flowsintApiBaseUrl`: корень API Flowsint **без `/api`**, например
`/flowsint-api` при общей маршрутизации. Отсутствующее или пустое поле скрывает
действие и не меняет текущие установки. HTTPS-адрес другого поддомена допустим
только внутри домена runtime-профиля, без credentials, query, fragment и порта.

Для legacy/dev-сборки: `VITE_FLOWSINT_API_BASE_URL`. В runtime-сборке адрес
не запекается в bundle. Общие правила и ограничения загрузчика сохранены.
Обновлять SDK или публиковать новые npm-пакеты не требуется.

При настройке окружения понадобятся общая cookie и CORS Flowsint для origin
Monitoring (credentials и `h-avl-project`), доступ к приложению в Auth,
а также настройки Cards → Flowsint из [backend-контракта](avl4-card-transfer.md).
Это задачи этапа 7; конфигурация сервисов и deployment здесь не менялись.
