# Flowsint: main_panel и платформенный SDK

Режим AVL4 использует внешний `main_panel` и опубликованные
`@avl4/core-sdk` / `@avl4/core-sdk-react` версии `0.2.1`. Панель единолично
проверяет сессию, выбирает проект и показывает повторный вход. Flowsint
наблюдает состояние SDK; собственного polling сессии, Keycloak-клиента,
JWT-входа или модального окна повторной авторизации в этом режиме нет.
Самостоятельный режим сохранён по умолчанию.

## Конфигурация и сборка

Сборка интегрированного интерфейса из `flowsint-app/`:

```sh
VITE_AUTH_MODE=avl4 VITE_RUNTIME_CONFIG=true npm run build
```

Оба переключателя фиксируются при сборке. Публичные адреса загружаются из
`/runtime-config.json` перед импортом приложения. Формат общий для AVL4:
`version: 1`, `application: "flowsint-ui"`, `profile`, `domain`, `settings`.
В `settings` используются общие поля `apiBaseUrl`, `assetBaseUrl`, `homeUrl`,
`loginUrl`, `logoutUrl`, `adminUrl`, `storageBaseUrl`, `panelCssUrl`,
`panelJsUrl`, `cookieDomain`, `cardsPrefix`, `mode`, `authBypass: false`.
Адреса должны соответствовать валидатору общего runtime-модуля: относительный
путь либо HTTPS в пределах указанного домена. Секреты сюда не передаются.
Ошибка загрузки или валидации останавливает запуск без fallback на адреса сборки.

Общий модуль `packages/runtime-config/src/index.ts` из UI-репозитория AVL4
сохранён неизменённой копией в `src/platform/vendor/runtime-config.ts`.
Происхождение и ревизия записаны рядом в README. Это позволяет собирать
самостоятельный checkout Flowsint без относительной зависимости от соседней репы.
Панель монтируется в отдельный `#main_panel`; её CSS/JS загружаются один раз,
а собственную runtime-конфигурацию она читает с origin своего модуля.

В production runtime-сборке Vite публикует только переключатели
`VITE_AUTH_MODE` и `VITE_RUNTIME_CONFIG`. Остальные `VITE_*` не попадают
в `import.meta.env`, в том числе из локальных env-файлов.

Для разработки допустим `VITE_AUTH_MODE=avl4` без runtime-переключателя:
общие legacy-переменные `VITE_BASE_API_URL`, `VITE_PANEL_JS_URL`,
`VITE_PANEL_CSS_URL` и другие `VITE_*` берутся при сборке. `VITE_API_URL`
сохранён как fallback адреса API и необязательная цель dev-proxy `/api`;
`VITE_PANEL_PROXY_TARGET` — необязательная цель `/panel` без переписывания пути.
В интегрированном окружении backend и воркеры должны использовать
`FLOWSINT_AUTH_MODE=avl4`, как описано в [backend-документе](avl4-auth-and-projects.md).

Корневой `.npmrc` содержит только публичный URL scoped-реестра `@avl4`.
Доступ к приватным пакетам настраивается вне Git. Зависимости фиксируются
корневым и отдельным `flowsint-app/yarn.lock`. Отстававший отдельный lock
синхронизирован с протестированными версиями корневого. Установка — Yarn Classic
`yarn install --frozen-lockfile` из выбранного корня сборки. Настройка
приватного реестра в Docker и публикация runtime JSON относятся к этапу 7:
существующий Dockerfile этим этапом не адаптирован к AVL4.

## Границы данных

- `createPlatformApp({ appId: "flowsint", projectScoped: true })` допускает
  интерфейс только после готовности панели, сессии, приложения и проекта.
- JSON-запросы используют `platformApp.http`, cookie credentials и текущий
  `h-avl-project`. Локальный Bearer-токен в AVL4 не отправляется.
- SDK отклоняет ответы предыдущего пользователя, session epoch или ревизии
  проекта до передачи вызывающему коду. `401` сообщает панели о проверке
  сессии без повтора запроса; `403` и ошибки сети не запускают отдельный вход.
- События задач используют `platformApp.openEventStream`. Переподключение
  ограничено двумя сетевыми попытками; EOF и HTTP-ошибки не повторяются.
- POST-поток AI использует тот же Axios gate через адаптер fetch для AI SDK.
  Смена проекта, пользователя, сессии, отзыв доступа или выход прерывают поток.
- При смене контекста SDK очищает Query и mutation cache. Дополнительно
  сбрасываются граф и выделение, flow-редактор, текущие чат/анализ, callbacks
  графа и открытые панели. Router создаётся заново, поэтому старые loader data
  и локальное состояние компонентов не переходят в следующий контекст.
- При смене проекта выбранное расследование сбрасывается на `/dashboard`.
  Первый прямой переход `/dashboard/investigations/<id>#pid=<project>`
  сохраняется; следующие ссылки Router также содержат `#pid`.
- Повторный вход выполняет панель, сохраняя полный текущий URL в `next`.
  Flowsint не перенаправляет платформенные `401` на собственный `/login`.
- В режиме AVL4 локальные формы login/register/profile и старый middleware
  перенаправляют на dashboard; auth-store не читает и не сохраняет JWT.
  Приглашения и списки участников расследований скрыты. Проверки действий
  разрешают все операции внутри доступного проекта; backend остаётся
  окончательной границей доступа.

## Проверки и ограничения

`npm test` проверяет транспорт, поздние ответы, статусы `401/403/503`, отсутствие
и несовместимость панели, очистку данных, logout, SSE/AI и runtime startup.
Для настройки интеграции обязательно выполнять полный набор, а не только
старые standalone-тесты. `npm run lint:check` проходит с существующими
предупреждениями. Production-сборка проверяется командой выше.

Полный `npm run typecheck` пока не проходит: на исходном UI воспроизведены
88 диагностик, после изменений осталось 86, новых по файлу/коду ошибки нет.
Среди исходных проблем — контракты редактора Tiptap, типы таблиц и графа.
Ошибки не скрывались исключениями из tsconfig; исправлены два затронутых
вызова типизированного доступа к данным Router в `use-can.ts`.

Локальная браузерная проверка выполнена с временным SDK host и тестовыми
API-ответами: первый запуск без панели, навигация с `#pid`, прямое открытие
расследования без роли, смена проекта и logout. Тестовый модуль удаляется
после проверки и не входит в приложение. Настоящие main_panel/Auth,
SSO-переходы между доменами, рабочие хранилища и установка в Docker требуют
сквозной приёмки этапа 7. Серверы и рабочие контейнеры не изменялись.
