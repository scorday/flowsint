# Cards → Flowsint: backend передачи карточек, v1

Реализован этап 5 [плана интеграции](avl4-integration-plan.md).
[Действие Monitoring](avl4-monitoring.md) реализовано; запуск окружения и живая приёмка остаются этапом 7. Обогащение не запускается.

## Операция браузера

Авторизованный запрос в Cards:

```http
POST /web/feed/cards/transfer-to-flowsint/
Content-Type: application/json
h-avl-project: <текущий проект>
```

```json
{
  "operation_id": "11111111-1111-4111-8111-111111111111",
  "card_id": "идентификатор карточки Cards",
  "card_type": "project",
  "investigation_id": "22222222-2222-4222-8222-222222222222",
  "sketch_id": "33333333-3333-4333-8333-333333333333",
  "refresh": false
}
```

`card_type` — `project` или `shared`. `operation_id` создаёт клиент один раз
на действие и сохраняет для повторов после тайм-аута. Браузер не передаёт
снимок, пользователя или проект в теле: неизвестные поля отклоняются.
Cards получает пользователя, проект и контекст личного проекта через
существующие Auth dependencies. Затем читает карточку через `AFeedQueriesRepo`
с обязательным проектом, проверяет её тип, принадлежность и отсутствие удаления.
Ни Flowsint, ни браузер не читают хранилища Cards напрямую.

Снимок содержит ID/тип карточки, исходный проект, shared ID, заголовок,
Markdown, URL источника, ссылку Monitoring с `cardId` и `#pid`, дату материала,
дату изменения источника и время захвата. Для shared исходный shared ID равен
ID самой карточки; у проектной копии берётся `copy_info.shared_id`.
Недопустимая для ссылки схема URL источника не переносится. HTML, вложения,
секреты, права источника и браузерная сессия не копируются.

Чтение shared не продвигает её в проектную карточку Cards, не запускает
рубрикацию и не создаёт побочных комментариев. Оригинал остаётся без изменений.

## Межсервисное доверие

Cards отправляет `POST /internal/avl4/card-imports` во Flowsint. В standalone
этот endpoint закрыт (`404`). В AVL4 он требует отдельную HMAC-подпись,
а не cookie/Bearer пользователя или внешние заголовки идентичности.

Подпись HMAC-SHA256 вычисляется над UTF-8 сообщением:

```text
cards-import-v1
POST
/internal/avl4/card-imports
<Unix timestamp>
<SHA-256 исходных байтов JSON-тела>
```

Заголовки — `h-avl-cards-timestamp` и `h-avl-cards-signature` (hex).
Допустимое отклонение времени — 300 секунд. Ключ длиной минимум 32 символа
задаётся только через private settings; для установки нужен случайный ключ.
Подпись действует исключительно для этой операции. Повтор того же доказательства
в пределах окна безопасен за счёт журнала `operation_id`; после окна Cards
повторно читает источник и создаёт свежую подпись для прежнего действия.

Подписанный контекст инициатора авторитетен только от настроенного Cards.
Приёмник повторно проверяет текущие пользователя, доступ к приложению Flowsint
и проекту через публичный Auth-клиент. Проверки повторяются перед SQL-записями
и перед графом. Возврат результата завершённой операции также требует свежего
доступа. Подпись Cards не разрешает другие endpoint Flowsint.
Ошибки межсервисной подписи не помечаются как потеря браузерной сессии.

Сетевой адрес приёмника задаётся конфигурацией, а не браузером. HTTP-клиент
не следует redirect, не использует environment proxy и не пересылает cookie
или сессионный токен. Connect timeout — 5 секунд; общий бюджет вызова —
30 секунд. Автоматического повтора POST нет. Для межсерверного канала нужна
защищённая сеть/TLS; ingress внутреннего endpoint настраивается при развёртывании.

## Идентичность и обновление

Идентичность материала — SHA-256 канонического массива
`[project_id, sketch_id, card_type, card_id]`. Заголовок служит отображению.
Разные карточки с одинаковым заголовком остаются разными узлами. Одна карточка
может присутствовать в нескольких графах. Shared и её проектная копия имеют
разные идентичности Cards; общее происхождение сохраняется в shared ID.

В Neo4j используется отдельный тип `avl4material` и `MERGE` по
`avl4_import_key`, а не общий механизм по `nodeLabel`. Нужен уникальный constraint
из [Cypher-файла установки](avl4-material-schema.cypher).
Без него импорт отказывается писать в граф. Синтаксис соответствует
[Neo4j 5](https://neo4j.com/docs/cypher-manual/5/constraints/create-constraints/).

Обычный новый импорт уже известной карточки возвращает материал с существующим
снимком (`action: "existing"`). Содержимое не меняется автоматически.
Для обновления клиент создаёт новый `operation_id`, передаёт `refresh: true`
и `expected_snapshot_hash` из предыдущего результата. Несовпадение хеша даёт
`409 SNAPSHOT_CONFLICT`; пользователь должен заново проверить снимок.
Snapshot hash исключает время захвата, но учитывает содержимое и происхождение.

Импортированные свойства защищены от обычного создания/редактирования узлов
и слияния с ручными сущностями. Геометрия графа, связи, удаление и заметки
остаются обычными действиями проекта. Повтор нового действия импорта может
восстановить удалённый узел; повтор завершённого `operation_id` возвращает
прежний результат без записи. Создатель материала не получает отдельных прав.

## Журнал и частичные сбои

PostgreSQL хранит `avl4_materials` и `avl4_import_operations` с обязательным
проектом, аудитом инициатора, временем создания/завершения и уникальным
`(project_id, operation_id)`. Незавершённая операция имеет `completed_at = NULL`.
Порядок:

1. Проверить проект → расследование → граф; заблокировать строки цели.
2. Зафиксировать материал/новый снимок и журнал действия одной SQL-транзакцией.
3. Повторно заблокировать материал и спроецировать актуальный SQL-снимок в Neo4j.
4. Зафиксировать Node ID и результат операции в SQL.

Если Neo4j или финальный SQL commit не ответили, первоначальный снимок уже
зафиксирован, а операция остаётся без результата. Повтор возобновляет проекцию
по прежнему material key. Снимок источника, заново прочитанный Cards при повторе,
не заменяет первый снимок этой операции.

Проекция всегда берёт актуальную SQL-ревизию материала. Запоздавшая незавершённая
операция не откатывает более новое явное обновление. Завершённый результат
остаётся историческим: повтор старой операции возвращает его, даже если материал
уже обновлялся. Другой пользователь проекта может импортировать тот же материал
новым действием; повтор чужого ключа с другой идентичностью инициатора отклоняется.

Блокировки PostgreSQL и уникальные ограничения сериализуют конкурентные записи;
после столкновения уникальности выполняется одна повторная проверка состояния.
Сбой между двумя хранилищами не является общей распределённой транзакцией.
Восстановление происходит при следующем запросе; отдельного фонового синхронизатора нет.

Снимок — самостоятельные данные проекта Flowsint. Удаление/ограничение оригинала
Cards не удаляет копию. Новое обращение через Cards снова требует доступный
оригинал; ссылка на него может перестать открываться. Автоматической каскадной
очистки копий нет.

## Ответы и ограничения

Успех: `200` с `version`, `operation_id`, `material_id`, `project_id`,
`investigation_id`, `sketch_id`, `node_id`, `snapshot_hash`, `action`
(`created/existing/updated`) и ссылкой `url` на граф с проектом.

| Ситуация | Результат |
| --- | --- |
| Нет доступа инициатора | `403 IMPORT_FORBIDDEN` |
| Чужая/отсутствующая цель | `404 TARGET_NOT_FOUND` |
| Обновление отсутствующего материала | `404 MATERIAL_NOT_FOUND` |
| Ключ действия использован для другого намерения | `409 OPERATION_CONFLICT` |
| Снимок уже изменился | `409 SNAPSHOT_CONFLICT` |
| Повторное столкновение записи | `409 IMPORT_BUSY` |
| JSON-тело больше 1 MiB | `413 CARD_SNAPSHOT_TOO_LARGE` |
| Неподдерживаемый контракт/данные | `422 INVALID_CARD_IMPORT` на приёмнике |
| Нет настройки, Auth, БД или Neo4j | `503`, без внутренних подробностей |

Структура ограничивает заголовок 4096 символами, Markdown 524288 символами,
ID 256 символами, URL 8192 символами. Весь межсервисный JSON ограничен 1 MiB.
Нет тихого обрезания. Cards ограничивает ответ 32 KiB и проверяет его контекст;
из ошибок приёмника передаются только перечисленные безопасные доменные коды.
Неизвестные ответы и сбои превращаются в общую ошибку сервиса, без raw body,
внутренних URL, токенов или SQL.

## Установка и проверка

В Cards: `FLOWSINT_IMPORT_BASE_URL`, `FLOWSINT_CARDS_IMPORT_KEY`,
`AVL4_MONITORING_BASE_URL`. В Flowsint: `FLOWSINT_AUTH_MODE=avl4`,
`FLOWSINT_CARDS_IMPORT_KEY`, `FLOWSINT_UI_BASE_URL` и существующие настройки
Auth/PostgreSQL/Neo4j. Ключ одинаковый у отправителя и приёмника; base URL
не содержит credentials, query или fragment. Без настройки операция закрыта.

Добавлена Alembic-ревизия `e4f5a6b7c8d9` после `d3e4f5a6b7c8`.
Downgrade запрещён при наличии импортированных материалов. Cypher constraint
устанавливается отдельно при подготовке хранилища. Runtime DDL из HTTP нет.
Упаковка настроек, миграция и обновление Cards API / Flowsint API и воркеров
выполняются на этапе 7 с отдельной авторизацией запуска.

Канонические DTO находятся в Cards `modules/feed/domain/flowsint_contract.py`;
копия во Flowsint `flowsint_core/avl4_import/contracts.py` совпадает по контракту.
[JSON Schema](avl4-card-import-v1.schema.json) описывает структуру v1;
дополнительные правила контекста и HTTP URL проверяются моделями. Общая golden
fixture в обоих репозиториях фиксирует байты JSON, HMAC, snapshot hash,
material key и fingerprint. Изменение контракта требует синхронного изменения
обоих потребителей и fixture.

Unit/API-проверки используют SQLite, имитацию графа/HTTP и публичный Auth-адаптер
с подменённым транспортом. Проверены запись после тайм-аута, SQL completion
failure, конфликты уникальности, отзыв доступа, два одинаковых заголовка,
обновление и поздний retry. SQL миграции сгенерирован офлайн. Живые PostgreSQL
блокировки, Neo4j constraint, TLS и SSO проверяются при сквозной приёмке;
миграции и рабочие сервисы в этом этапе не запускались.
