## Браузерный сценарий

Проверка через отдельную сессию agent-browser, production FastAPI routes/auth
и Vite, временную SQLite и loopback Neo4j. Использованы только синтетические
Alice VK (`id123`), Bob VK (`id456`) и Acme.

1. Friends содержит Alice, Bob и FRIEND_OF; Work изначально содержит только Acme.
2. В Work через «Investigation objects» включены существующая Alice и отдельно
   выбранная WORKS_AT. Friends сохраняет прежний состав.
3. Bio Alice изменено на Work. На Friends видно новое значение и история
   прежнего наблюдения; координаты и состав схем независимы.
4. Из выбранной Alice создана третья схема. После перезагрузки в ней тот же
   профиль. Исправлен найденный stale cache переключателя схем; регрессия покрыта
   `new-sketch.test.tsx`.
5. Alice убрана с третьей схемы. В общем диалоге она остаётся доступной вместе
   с Bob и Acme.
6. Alice удалена из расследования на Work с отдельным подтверждением.
   На Friends остаётся Bob, связанные с Alice отношения исчезают.

Браузерная сессия и временные API/Vite остановлены после проверки.

## Native backup и rollback

На Neo4j Community 5.26.0 / JDK 21 выполнен настоящий offline `database dump`,
затем `database load` в отдельные каталоги данных. Это подтвердило смену UUID
базы внутри `elementId`, при сохранении содержимого и номеров записей.

Финальный контрольный dump содержал 26 синтетических узлов и 6 связей.
После восстановления сверены полные количества, constraints и архивные записи
выбранного расследования (2 узла, 1 связь, все свойства и endpoints).
SQL-копия восстановлена в отдельный файл. `--restore-references` в dry-run
оставляет её неизменной, apply исправляет одну строку Log с node/edge ID,
повтор исправляет 0 строк. Свободный текст доказательства сохранён.

Тест SQL восстановления выполнен на SQLite. PostgreSQL dump/restore и реальные
пользовательские данные не затрагивались. Перед разрешённым rollout оператору
всё равно нужен согласованный PostgreSQL/Neo4j backup и проверка его восстановления
для конкретного окружения по runbook. Живые внешние провайдеры VK не вызывались.
Все созданные тестовые Neo4j после проверок остановлены.

## Границы результата

Работа подготовлена в локальной ветке, без push или deployment. На серверных и
пользовательских данных миграция не запускалась. SQL-модели расследований и схем
сохраняются; изменение принадлежности графа выполнено в Neo4j и сервисных контрактах.
Между разными расследованиями сущности по-прежнему изолированы.

Изменения общих атрибутов видны при загрузке схемы и возврате фокуса; новая
межоконная доставка realtime-событий в эту работу не входит. Пределы размера
графа, архивные tombstones удалённых SQL-схем и правила обработки нескольких
прежних раскладок перечислены в runbook.
